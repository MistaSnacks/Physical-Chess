**Owns:** `src/pages/login.astro`, `src/pages/signup.astro`, new `src/pages/forgot.astro`, `src/pages/verify.astro`, `src/pages/privacy.astro`, `src/pages/who.astro`, `src/pages/family/**`, new `src/pages/family/report/[player].astro` (client-rendered by id: use a single page `src/pages/family/report.astro?player=` if dynamic ids are a problem in static output), `src/lib/wix.js`, `src/lib/repo/wixRepo.js`, `src/lib/repo/localRepo.js`, `src/lib/actions.js` (add, do not break), `src/lib/auth-guard.js`, new `src/lib/export.js`, `src/components/quest/AvatarPicker.astro`, `PlayerCard.astro`.
**May edit (append):** `theme.css` under `/* === WP4: accounts === */`.

## Goal
The whole grown-up side: sign in / up / reset / verify in the Quest look, the player picker, family home, add/edit/delete player, settings, the report card with CSV/JSON download, and a `wixRepo` that is correct against the SDK docs even though it cannot be exercised until the client creates the OAuth app.

## Deliverables
1. **Auth screens** (SPEC §2.1, §2.1.1): `/login`, `/signup`, `/forgot` (`sendPasswordReset`), `/verify` (6-digit code → `processVerification` → `beginRedirectExchange`). Every `loginState` / `errorCode` from the Wix docs maps to a plain-language message. reCAPTCHA v3: load the script only when `PUBLIC_RECAPTCHA_SITE_KEY` is set, add the token to a hidden field, and pass it to `wix.auth.login/register` per the Wix "Add reCAPTCHA to a custom login page (JS SDK)" doc (read it with the Wix docs if you can; otherwise leave a clearly marked TODO with the doc URL). `?next=` round-trips. In demo mode `/login` shows the demo card (exists) and the others show a friendly "needs the Wix connection" note.
2. **Player picker** `/who`: polish the WP0 version (PlayerCard component, level under the name from each player's snapshot: call `getRepo().listEvents` per player and `derivePlayer` — keep it fast for ≤ 6 players), "Grown-ups" link with a simple gate (a 2-digit math question, e.g. "What is 7 + 5?") before `/family`, since kids share the device.
3. **Family** `/family`: players with report links, add player, settings card: leaderboard opt-in (`updateAccount({ leaderboardOptIn })`), display name, email (read-only from Wix), "may play in class" per player; sign out; **Delete my account** (two-step confirm; demo: `resetDemo()`; Wix: call `DELETE /api/account` which WP6 implements. If the route is missing, show "Contact ACE to delete your account" and leave a TODO).
4. **Edit player** `/family/players/[id]` (client-rendered from the query or a static catch-all): name, apelido, avatar (AvatarPicker), program (by invite code entry: `programByInvite`), birth year, may-play-in-class, **Delete this player** (two-step; `deletePlayer`).
5. **Report card** `/family/report?player=<id>`: level, XP, readiness checklist, lessons done with stars, patches, corda history, roda-weeks, practice log (each `lesson.drill.done` with a "I saw it" button that records `practice.confirmed` if not already confirmed for that drill), timeline of events (last 50). **Print** styles (@media print: cream on white, one column). **Download CSV** and **Download JSON** (`src/lib/export.js`: builds a Blob client-side from the ledger; CSV columns: occurredAt, type, moduleId, lessonId, xp, stars, source, payload).
6. **Privacy page** `/privacy`: plain-language text per SPEC §3.3 (what is stored about a child, how to delete, who to contact). Link it from signup and the footer (edit `src/directions/quest/Footer.astro` minimally).
7. **wixRepo**: review every SDK call against `@wix/data` (`items.query/insert/update/get`, `.eq`, `.ne`, `.ascending`, `.limit`, `.find`, `hasNext/next`) and `@wix/members` (`getCurrentMember`). Fix anything wrong. `listEvents` must page. `appendEvents` must not do one query per event: query `clientEventId` `.hasSome([...])` once, then bulk insert (`items.bulkInsert` if available in the installed SDK version, else sequential inserts). Keep the outbox contract.
8. Demo mode must keep working exactly (smoke test `SMOKE OK`).

## Done when
Full guardian flow works in demo (sign in → add player → edit → report card → CSV downloads → delete player → sign out). Screens at 390 and 1440 in `screenshots/wp4/`. Report `agents/reports/WP4.md` lists everything that can only be verified once the client ID exists.
