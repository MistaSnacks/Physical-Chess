# WP11-12: quiz-format groundwork and inert Cores

Branch `wp11-12-groundwork` (based on `client-notes-v3`, includes WP8 `67c8538`). Port **4414**. No new dependencies. `node_modules` left as the worktree symlink. Tested in **demo mode** only.

Nothing kids see changed. `Quiz.astro`, `Check.astro`, the Desafio page, every display, overlay, CSV export and storage field are as they were.

## What I built

### WP11 (R11.1-R11.4)

- **`src/lib/quiz.js`** (new, pure)
  - **Kinds:** `multipleChoice` (the default when `kind` is missing), `matching` (`pairs: [{ left, right }]`) and `fillBlank` (`accepted: []`, optional per-question `foldAccents`). `explain` is optional on all three.
  - **`normalizeAnswer`:** Unicode NFC, trim, collapse whitespace (NBSP too), lower case. It also turns smart quotes into plain ones, because tablet keyboards insert them. Accents fold away only when `foldAccents: true` is set. A precomposed é and an e with a combining accent always count as equal.
  - **`scoreQuestion`:** returns exactly one result per question (`{ questionId, kind, correct, answer, explain, pairs? }`).
    - Matching is wrong if any pair is wrong, a pair is missing, or the answer names a left side the question doesn't have. Per-pair detail is included only so a future screen can show it.
    - A blank is wrong if it matches no accepted answer, and an empty answer is always wrong.
    - `answerPayload()` gives the same `{ questionId, correct }` that the lesson page records today, so WP8's `allowedXp` pays 10 per question, never 10 per pair.
  - **`questionProblems` / `quizProblems`:** one set of validation rules, shared by `content:check` and the importer. A question with no `correctIndex`, `pairs` or `accepted` gets "has no answer". The function also catches unknown kinds, out-of-range indexes, duplicate choices, fewer than 2 pairs, duplicate left or right sides, empty accepted answers, a non-boolean `foldAccents`, empty `explain`, and duplicate question ids within a quiz.
  - **An attempt state machine** (`startAttempt`, `submitAnswer`, `resetAttempt`, `attemptSummary`, `attemptAnswers`) that matches what Quiz.astro does today:
    - 3 hearts, and a wrong answer costs one and reveals the answer.
    - At 0 hearts the attempt goes to `retry` and its answers are dropped.
    - Submitting the same question twice returns the same state object unchanged.
    - Reset is idempotent.
    - This is what the R11.5 screens can drive after D6. Nothing uses it yet.
- **`scripts/content-check.mjs`**
  - The quiz section now calls `quizProblems()`, so it learns the new kinds and rejects questions with no answer. Legacy messages are worded as before.
  - It also fails if a live lesson uses a kind other than multiple choice: "Quiz.astro can't show … yet (waits for D6)". Quiz.astro would crash on `q.choices.map` otherwise. **Remove that guard in R11.5.**
  - Every pin is unchanged: 5 questions in Music and in Culture, Music q1-q3 word for word, 3 in Roda Ready.
- **`scripts/quiz-import.mjs`** (new)
  - Runs as `node scripts/quiz-import.mjs <sheet.csv> [--out <file.json>]`. JSON goes to stdout by default; warnings and the summary go to stderr.
  - It has its own RFC 4180 CSV parser: quoted fields, `""` escapes, commas and line breaks inside quotes, CRLF/LF/CR, and a BOM.
  - Header names are matched loosely (case, spaces, punctuation and "(optional)"-style parentheses are ignored).
  - **Columns:** Cor, module, topic, kind, prompt, options or pairs, accepted answers, explanation. I added two optional columns:
    - **ignore accents** (yes/no): D6 says accent folding is approved per question, so ACE needs somewhere to approve it.
    - **id**, to pin question ids. Otherwise ids are `<topic-slug>-<n>` in row order.
  - Every problem comes back as one message with the row number, the start of the prompt and how to fix it, e.g. `Row 2 ("Which instrument leads the roda?"): no answer. Put the right option in "accepted answers", …`. Examples: no answer, unknown module, kind or Cor, an answer that isn't one of the options, a pair with no `=`, more than one multiple-choice answer.
  - If any row is bad, nothing is written (exit 1). As a backstop, it also runs the same `quizProblems()` that content:check uses.
  - It refuses any `--out` that isn't a `.json` file, so it can't overwrite `lessons.js` (exit 2).
  - Output is deterministic: no timestamps.
  - Rows are grouped into one quiz per module + topic. Each question carries `cor` (a Core id), `kind`, the answer fields, `explain` and `sourceRow`.
  - It warns about rows whose prompt starts with "EXAMPLE:".
- **`docs/quiz-sheet-template.csv`**: three example rows, one per kind, each prompt starting with `EXAMPLE:`. The fill-in-the-blank row (`Axé`, ignore accents = yes) shows how accent approval works.
- **`docs/quiz-sheet-guide.md`**: a plain-language guide to the columns for ACE, with no em dashes.

### WP12 (R12.1, R12.2 data only, R12.8)

- **`src/content/cores.js`** (new, inert)
  - The nine Cores in table order, with ABADÁ spellings: Crua, Ouro, Sol, Mar, Floresta, Ametista, Camaleão, Rubi, Diamante.
  - Each has `order`, `id` (ASCII slug), `title`, `cordColor`, `color` (hex), `token`, `meaning`, `xp` and `reviewNeeded: true`.
  - **Colors:**
    - Crua uses `--quest-corda-crua`, and Camaleão uses `--quest-mango-shadow` (#7a4a00, a cord brown).
    - Ouro and Sol reuse CORDAS' yellow `#ffc93c` and orange `#ff8a1f`, so a Core and a corda of the same color match.
    - Mar, Floresta, Ametista and Rubi are hex values close to the cord colors.
    - Diamante is pure `#ffffff`, so it never reads as Crua's natural.
- **`src/lib/game/cores.js`** (new): `coreFor(xp)` returns `level` (the Core's order, 1-9), `id`, `title`, `color`, `meaning`, `xp`, `xpInto`, `xpToNext`, `xpSpan`, `percent`, `isMax` and `nextTitle`. It is exported from `game/index.js`.
  - **Rounding differs from `levelFor` on purpose:** `percent` rounds *down* (capped at 99 below Diamante). The bar is never full until the next Core is reached; `levelFor` rounds, so it shows 100% at 699 XP. `levelFor` itself is untouched.
- **`derive.js`**: the snapshot gains `core: coreFor(xp)`. `level` and `levelFor()` are unchanged, and `snapshotFields()` still persists only the old fields, so storage didn't change.

### Tests

- **`test/quiz.test.mjs`** (35 tests). All fixtures are inline.
  - Normalization, variants, case, spacing, accents (strict versus approved), smart quotes, NFC.
  - Matching: all pairs right, one wrong, missing, extra left, array form.
  - Multiple choice parity with Quiz.astro, and purity (fixtures are deep-frozen).
  - Every live quiz question validates, has no `kind`, and scores as before; the pins hold.
  - The no-answer rejection for each kind, and malformed questions.
  - Hearts, retry dropping its answers, double submit returning the same state, reset idempotence.
  - Credit through WP8's `withAllowedXp`: a matching question pays 10 not 30; reset, replay and double submit add 0 XP; wrong-then-right pays once; stars come from `starsFor` as before.
  - The CSV parser edge cases, the shipped template, each kind's import, row-numbered rejections, duplicate pairs and ids, missing headers.
- **`test/cores.test.mjs`** (15 tests)
  - The exact table, `reviewNeeded`, every `xp` being a `LEVELS` threshold (with levels 4, 7 and 10 folded), ids, and colors and tokens against `tokens.css`.
  - Boundaries at 99/100 through 3,849/3,850, plus the folded 449/450, 1,349/1,350 and 2,699/2,700, which don't move the Core.
  - Percent math, Diamante as the max, bad input, and `snapshot.core` alongside an unchanged `level` (560 XP gives Sol and level 4, Cocorinha).
  - **R12.8:** pinned shipped thresholds for `LEVELS` and the Cores. A test fails if any threshold rises or a level or Core is removed; lowering one is allowed. A further test proves the guard catches a raised threshold.
